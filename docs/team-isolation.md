# Claude 组织隔离与对话重置

组织使用 Claude 授权结果中的真实组织 UUID，独立于计费分组、号商和平台用户。组织名称及 UUID 仅向管理员输出；号商、用户和 ops 不获得这些字段。管理员在账号页查看组织，在节点代理池查看归属、容量与分配历史。

## 对话归属

一把 API Key 可以使用其分组准入范围内的多个组织。一个对话阶段只在一个组织内选择账号；额度、窗口、代理、节点等原因导致换号时，候选仍限定在该组织。

当前请求在整个组织内没有可用账号后，平台结束旧阶段并建立新阶段，再选择其他组织。新组织只接收当前独立问题和本轮独立附件；旧消息、system/developer、摘要、工具结果、挂起调用、续接句柄与旧 worker 状态不随之转移。基础系统提示词由平台重新生成。

对话阶段和清空边界保存在数据库。客户端后续再次提交完整旧历史时，网关仍裁去旧阶段的内容。无法可靠匹配边界时，接受请求并保守地以当前问题重新开始。只有工具结果、没有独立新问题时，返回正常助手提示，告知上下文已清空，需要发送新问题；不自动重做先前已经执行的工具操作。

明确会话标识优先使用客户端会话头或 metadata session ID；没有稳定 ID 时使用内容指纹兼容，不因为缺少 ID 拒绝服务。IP、User-Agent 和软件版本不能单独证明对话身份。内容指纹存在歧义时允许丢失上下文连续性，不能带旧历史跨组织。

响应可提供不含组织身份的对话/阶段标识和上下文重置提示。已经发给客户端的模型输出无法撤回，不能在同一个流里拼接另一个组织的答案。

## 固定代理与容量

账号固定绑定代理。**自动分配先铺开（2026-10-29 运营决定）**：在可选范围（节点或指定 IP 组、组织兼容的出口）内挑负载最低的出口——每个出口先各放一个账号，范围内所有出口都有一个后才补第二个，都有两个后才用第三个名额；同负载按探测顺序轮转。此前的规则是先把一个出口填到两个再开新出口，连续上号会落在同一 IP。三为硬上限，已绑定账号和正在上号的有效预留一起计数。暂停、窗口耗尽或临时失活不会释放账号的绑定；重新授权原账号不重复占名额。

出口组织归属独立于当前绑定，删除账号或池成员不会擦除历史。相同实测出口 IP 的不同代理配置、不同节点合并计数。出口探测结果、组织认领、账号绑定/释放和冲突事件单独留存；不能用心跳的当前分配快照代替历史。

首次接入且组织未知时，需要从未归属其他组织的出口完成发现；不能借用其他组织的出口探测。已实际发出授权请求但组织无法确认的出口进入隔离。已知组织 UUID 可以直接使用该组织的可用容量，最终仍与授权结果核对。

动态代理的探测结果只是一次观测。供应商可能在后续连接更换出口，应用无法证明它永远不被其他客户使用；需要固定独享公网 IP 的部署应使用受控的固定出口。变化和冲突必须重新校验、记录，不能把代理 URL 哈希当作真实公网 IP。

## 执行资源

网关、控制面和节点共同校验组织、账号、代理、对话与阶段。旧协议节点不能接收新的隔离执行任务。账号保持自己的固定设备身份，新组织使用新组织账号的身份。

跨组织强制重置精确针对旧对话阶段：取消排队和在途执行、终止对应进程、注销挂起工具调用，禁止迟到事件进入新阶段；不关闭其他对话的 worker。

每组织可使用独立的 provider-node 服务实例，配置 `PROVIDER_TEAM_ID`，分别使用系统身份、配置目录和状态目录。代码变更不等于已经部署操作系统或服务器隔离；部署说明与服务模板见 provider-node 的说明和 packaging 目录。

发布时必须同步更新控制台、网关、前端和节点 bundle。节点需要报告 `team_isolation_v1` 才能接收新的隔离任务；旧节点不能借用新隔离代理。是否实际启用每组织独立系统服务，以[本次部署记录](deployment/team-isolation-2026-10-27.md)为准，不能把共享节点上的协议隔离描述为独立操作系统隔离。

2026-10-27 已完成主服务器和三个标准节点的线上版本更新。新组织、账号和代理池未从旧数据回填，当前新隔离池为空；每组织独立 OS 服务模板已安装但没有启动实例。新供给需按本规则接入后才会进入隔离调度。

只对执行过旧阶段的节点等待重置确认。节点不确认时撤销其连接、保留重连后的重置任务；旧阶段已由数据库代次封锁，不阻止健康的新组织接手。断联节点上的操作系统进程无法被平台即时终止，重连后会根据持久代次强制撤销。

## 现有数据

迁移 21 仅新增结构，不推断、回填、修改或删除旧账号、代理绑定、会话、用户、API Key、余额和账本。旧代理不会被自动认定为新建的隔离资源，旧的无 team 订阅账号不进入新隔离池。新接入与旧记录具有同一上游账号 UUID 时，也不会借此回填旧记录；已管理的新账号仍执行组织与身份冲突检查。

自动化验证使用临时数据库和本地上游替身。生产部署的代码版本、迁移、节点能力、只读冒烟和数据保留验证记录在[发布记录](deployment/team-isolation-2026-10-27.md)，不运行旧数据清理或自动补归属任务。

管理员查询接口：

- `GET /api/admin/teams`
- `GET /api/admin/teams/events?proxyId=...&teamId=...`

历史接口保留事件发生时的组织与账号标识，不根据当前账号归属改写过去的记录。

## 2026-10-28 审计修复补充

并发/RPM 暂时不足只在当前 team 有界等待，等待超时返回可重试错误，不清空主对话。额度/凭据等真正耗尽才进入新的清空阶段。账号与用户准入均使用跨网关共享租约；失去租约会取消上游。

生产执行仅使用运维配置批准的节点。共享节点主管进程为每个 team 创建不同的 Linux 系统用户，账号配置目录和会话 scratch 以该 UID、0700 权限隔离；无法创建身份则拒绝执行，不降级到共享 UID。不同 team 仍共享同一内核，这不是 VM 隔离。管理口需要独立 0600 凭据。

迁移 22 同样仅新增结构。后台窗口刷新、上号维护、代理状态和设备心跳不修改未管理的旧账号/代理/任务；旧无价格快照账单不自动退款。完整清单见 [审计修复记录](audit-remediation-2026-10-28.md)。
